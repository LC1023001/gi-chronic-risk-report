# 数据质量三陷阱与口径规则

保险公司核心系统导出的赔案明细存在三个系统性数据陷阱。**必须在分析前完成诊断，否则时间维度结论全错。**

## 陷阱一：批次报销伪像（最常见、最致命）

**机理**：团体补充医疗普遍为"攒票报销"模式——员工积累数月发票后一次性提交。系统登记的"出险日期"＝该批次**最早发票日期**，而非真实就诊日。

**判定特征（命中任意两条即确认）**：

| 特征 | 典型表现 |
|---|---|
| 出险月度畸形 | 历年 1 月出险暴增（占全年 20%–40%），或季度初（1/4/7/10 月）集中 |
| 报案-出险间隔异常 | 中位间隔 > 90 天（正常单次就诊应 < 30 天） |
| 单案发票张数高 | 案均发票 > 5 张（极端个案 100+ 张） |
| 案件摘要佐证 | 摘要文本显示"取药""开药"或多日期清单 |

**处置规则**：

1. **时间维度分析（月度/季度分布、就诊节奏）一律改用报案日期口径**
2. 出险日期仍用于年度归属（保险年度核算），但需在报告附录声明口径
3. 报告建议中可将"报销批次周期长（半年一批）→ 员工垫资压力大"转化为线上报销/按月提交的服务改进建议（正面表述，见 report-perspective.md）
4. 验证方法：交叉表"报案月 × 出险月"，看每个报案月对应的出险月是否散布多月

## 陷阱二：导出行数上限

**机理**：核心系统报表导出常设单文件行数上限（常见 2500 行），超限时静默截断。

**判定特征**：
- 某年度件数恰为 2499 / 2500 / 4999 等临界值
- 年度件数与趋势严重背离（如 2023 年 2499 件、2024 年 0 件）

**处置规则**：
1. 命中临界值时在报告附录注明"该年度数据可能不完整"
2. 提示用户按险种/时间段分批重导
3. 统计报表（xlsx）件数 vs 明细文件行数交叉验证——差额即为截断量

## 陷阱三：年度缺失与进行中年度

**判定特征**：
- 出险年度不连续（如 2020/2022/2023/2026，缺 2021/2024/2025）
- 最近年度件数/件均骤降（报案滞后：员工还没报，或保单未到期未决）

**处置规则**：
1. 报告标题与封面明示覆盖年度（"2020/2022/2023/2026 保单年度"），**不得写成"近四年"等误导表述**
2. 进行中年度（未满期）在年度趋势图表中标注"进行中"，不纳入同比增速结论
3. 缺失年度提示用户：补齐后重跑生成器即可更新报告
4. xlsx 统计报表可提供保费口径（保险期间、保单号、保费、赔付）——用于对照合作全周期，但缺失年度的明细无法补分析

## 其他数据口径规则

| 事项 | 规则 |
|---|---|
| 金额口径 | 分析主口径用**应给付金额**（实付）；核定金额可作参考，作废案件（赔案类型含"作废"）天然给付为 0，计入件数不计入金额 |
| 人级去重 | 以**报案人证件号**为唯一键（姓名可能重名；若证件号已脱敏为相同掩码则退回姓名+证件号组合） |
| 住院/门诊 | 出险类型字段含"住院"字样归住院，其余归门急诊 |
| 年龄 | 取出险时登记年龄；异常值（0/空/999）剔除并计数 |
| 病案同人 | 大额案件需做同人关联：同一证件号多个大额案件合并为一个"人"呈现（避免同一人两案被当成两个人） |
| 诊断缺失 | 诊断名称为空/“无”的归入"症状体征及未特指"，不剔除 |
