# 团单慢病风险减量评估报告

## Overview

从团体保险赔案明细数据（保险公司核心系统导出的 xls/xlsx）生成面向投保单位人力资源部门的**员工健康风险管理增值服务报告**：疾病出险分布、慢病人群画像、红黄绿风险分层、大额个案分析、慢病风险减量方案与全年服务计划。数据经病种归类与队列分析后由 Python 生成器产出交互式 HTML 报告（ECharts 图表 + 结构化表格），并经四重校验（结构/语法/敏感词/隐私）后交付。

## 工作流总览

```
1. 数据探查   → 摸清文件格式、表头结构、企业归属、年度范围
2. 质量诊断   → 识别批次报销伪像、导出截断、缺失年度，确定分析口径
3. 数据画像   → 年度分布、住院/门诊、人员去重、金额分层
4. 病种归类   → ICD 类目关键词映射 + 慢病队列识别
5. 深度分析   → 慢病 vs 非慢病、红黄绿分层、大额个案、高频人群
6. 报告生成   → 运行 scripts/analyze_claims.py 出 JSON，再数据驱动生成 HTML
7. 四重校验   → scripts/validate_report.py + 数字交叉核验
8. 交付沉淀   → present_files 交付 + 记录数据口径与生成器留存
```

**重要：第 1–2 步绝不可跳过。** 赔案数据有三个系统性陷阱（批次报销伪像 / 导出行数上限 / 年度缺失），不先诊断口径直接分析会得出错误结论（详见 `references/data-diagnostics.md`）。

## Step 1 数据探查

用户提供的文件通常分两类：

| 文件 | 格式 | 读取方式 |
|---|---|---|
| 赔案明细清单（一人一档或一年一档） | 真实 xls（BIFF） | `xlrd.open_workbook()` |
| 团体保单赔付统计报表 | xlsx（常含图片/控件） | openpyxl 读不出时用 zipfile 解析 `xl/sharedStrings.xml` + `sheet1.xml` 重建 |

明细清单典型结构（57 列）：第 0 行标题、第 1 行表头、第 2 行起数据。关键列位（以表头名定位，勿硬编码列号）：

- 赔案号(0)、保单号(1)、分单号(2)
- 出险类型(9，含"住院"字样区分住院/门诊)、案件状态(10)
- 核定金额(11)、清算金额(14)、**应给付金额(15)＝分析主口径**
- 报案人证件号(8，人级去重键)、性别(6)、年龄(7)
- 投保单位(20)、出险日期(21)、报案日期(22)
- 诊断名称(42)、案件摘要(52)、发票张数(47)、报案方式(46)

探查动作：
1. 文件头 `head[:8]` 判断真实格式（`.xls` 后缀可能是 HTML 伪装）
2. 每个文件的单位字段(20)去重 → 确认企业归属与文件分组
3. 出险日期(21)年度范围 → 确认覆盖年度
4. 多文件同构校验（列名一致性），然后按企业分组合并

## Step 2 质量诊断（口径三陷阱）

详见 `references/data-diagnostics.md`，此处为判定要领：

1. **批次报销伪像**：出险日期＝报销批次最早发票日，非真实就诊日。判定特征：某月出险暴增（如历年 1 月、季度初）＋ 报案-出险间隔中位数超 90 天 ＋ 单案发票张数均值高（>5）。**命中则时间维度分析一律改用报案日期口径，并在报告附录声明。**
2. **导出行数上限**：系统导出常限 2500 行。年度件数恰为 2499/2500 时须提示用户补导或说明截断。
3. **年度缺失**：出险年度不连续（如 2020/2022/2023/2026）时，报告标题注明覆盖年度，并提示缺失年度可补齐后重跑。

## Step 3 数据画像

按企业分组计算（scripts/analyze_claims.py 已封装）：

- 总盘：件数、应给付合计、出险人数（证件号去重）、件均、人均
- 年度趋势：各年件数/给付/人数/住院门诊拆分
- 金额分层：0–300 / 300–500 / 500–1k / 1–3k / 3–10k / 10–30k / 30k+
- 年龄段（<40 / 40–49 / 50–59 / 60–69 / 70+，适老化群体可调档）、性别
- 就诊频次分布（人级件数：1 次 / 2–3 / 4–6 / 7–9 / 10+）
- 报案渠道按年、发票张数、作废件数

## Step 4 病种归类

诊断名称(42)为自由文本，用关键词优先级映射到 16 个 ICD 类目（恶性肿瘤最先匹配，症状体征兜底）。慢病队列识别用 25 个慢病关键词（人级标记：任一案件命中即为慢病人群）。完整词库见 `references/disease-catalog.md`，脚本已内置。

**特有发现点**："不适和疲劳"等"症状体征及未特指"占比高（>15%）时，抽样核验该人群的其他诊断——通常实为慢病用药批量报销（诊断未规范登记），应作为独立建议项（诊断登记规范化专项）写入报告。

## Step 5 深度分析

1. **慢病 vs 非慢病对比**：人数占比、给付占比、人均给付倍数、住院率差异——报告的核心论据
2. **红黄绿分层**（人级）：
   - 红：慢病 且（累计件数≥7 或 累计给付≥2 万）
   - 黄：慢病 其余
   - 绿：非慢病
   - 输出各层人数/件数/给付及占比（红层通常 15%–20% 人贡献 70%+ 给付）
3. **大额个案 TOP10**：金额、诊断、摘要、发票张数、年度；同人多次大额需合并呈现（同人关联分析）
4. **肿瘤队列**：件数、人数、给付，TOP 个案
5. **高频高额人群画像**：性别、年龄段交叉

## Step 6 报告生成

**6.1 运行分析脚本**：

```bash
python <skill路径>/scripts/analyze_claims.py \
  --files "文件1.xls" "文件2.xls" ... \
  --unit "企业全称" --short "简称" \
  --out _analytics.json
```

输出全维度 JSON（年度/病种/分层/个案/频次/渠道），后续所有报告数字从 JSON 取值，**禁止手写硬编码数字**。

**6.2 生成 HTML 报告**：参照会话工作区 `_gen_reports.py` 模式——样式与 ECharts JS 框架作为固定模板，叙事配置（企业画像定性、特色发现、建议条目）按企业定制，数字全部由 JSON 计算 f-string 注入。报告结构与图表规范见 `references/report-structure.md`。

**6.3 视角红线（最高优先级规则）**：报告全程为 HR/员工健康/企业费用效率视角。禁词表与转译对照见 `references/report-perspective.md`，摘要：

- 禁：核保、定价、赔付率、盈亏、亏损、费率、涨价、精算、满期、超赔、承保、免赔额、Stop-Loss、续保率、加保率、粘性、离不开、换不起
- 收益表述用"减损/节约医疗费用"，趋势表述用"医疗费用增速"，尾部分析用"大额理赔个案"
- 语言通俗：图表为主、结论框精炼；**不使用"一句话："式标签**（AI 味）

## Step 7 四重校验

```bash
python <skill路径>/scripts/validate_report.py 报告.html
```

覆盖：① HTML 标签配对（HTMLParser 栈式）② 图表容器 ID 与 mk() 调用一一对应 ③ JS 语法（node --check）④ 敏感词扫描（视角禁词表）⑤ 隐私扫描（证件号残留、手机号、姓名字段）。

人工追加：抽查 5–8 个关键数字（总给付、慢病占比、分层人数）与 JSON 计算值一致；硬编码数字与脚本实算值偏差 >0.5 个百分点必须修正生成器重跑。

## Step 8 交付与沉淀

1. 报告命名：`{简称}-健康风险管理服务报告-{YYYYMM}.html`
2. present_files 交付，附数据口径说明（批次报销口径、缺失年度、进行中年度）
3. 工作区保留生成器脚本——补充数据或改口径只需改配置重跑
4. 工作日志记录：企业、数据范围、口径决策、特色发现
